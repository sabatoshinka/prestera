# Prestera — VPS на Ubuntu 22.04

Этот комплект запускает сервер знакомства и coturn. Приложение устанавливать на VPS не нужно.
Клиентам нужен Prestera 0.5.0 или новее. Домен в примере — `prestera.example.org`: замени его своим доменом. Общего сервера по умолчанию нет.

## 1. DNS и порты

Создай A-запись своего домена, например `prestera.example.org`, с публичным IPv4 VPS. Если пользуешься DNS-прокси, отключи проксирование для этой записи (DNS only). Не добавляй AAAA без настроенного IPv6.

Нужны входящие порты в сетевом экране провайдера и Ubuntu:

- TCP 80, 443 — HTTPS и выдача сертификата;
- UDP и TCP 3478 — STUN/TURN;
- UDP 49160–49415 — медиаретрансляция.

Не открывай 8787 наружу: он слушает только 127.0.0.1.
Если используешь UFW, добавь разрешения: `sudo ufw allow 80/tcp`, `sudo ufw allow 443/tcp`, `sudo ufw allow 3478/tcp`, `sudo ufw allow 3478/udp`, `sudo ufw allow 49160:49415/udp`. Не включай и не сбрасывай UFW вслепую: сохрани доступ SSH.

## 2. Docker и запуск

Установи Docker Engine и Compose plugin по официальной инструкции: https://docs.docker.com/engine/install/ubuntu/ .
Проверь `docker compose version`. Скопируй эту папку на VPS, например в `~/prestera-server`.

```bash
cd ~/prestera-server
bash setup.sh
# Укажи домен и внешний IPv4 этого VPS.
docker compose up -d --build
docker compose ps
docker compose logs --tail=50 signaling https turn
```

`setup.sh` создаёт отдельные случайные ключи для создания комнат и TURN. Повторный запуск их не перезаписывает.
Сохраняй `.env` и `turnserver.conf` приватными, не загружай их на GitHub.
Если VPS находится за NAT облачного провайдера, coturn может потребовать `external-ip=ВНЕШНИЙ/ВНУТРЕННИЙ` в `turnserver.conf`.

В этом комплекте Caddy занимает порты 80/443. Если там уже Nginx/Caddy или другой сервис, не запускай второй: исключи службу `https` из Compose и настрой существующий reverse proxy для HTTPS `/relay` и `/health` на `127.0.0.1:8787`, с поддержкой WebSocket и длительных соединений. Для запуска только двух служб: `docker compose up -d --build signaling turn`.

## 3. В приложении

1. «Создать комнату» → «Через VPS · без VPN».
2. Адрес: `https://prestera.example.org` (замени на свой домен).
3. Ключ создания комнат: значение `PRESTERA_SERVER_KEY` из `.env`.
4. Создай комнату и отправь приглашение другу. Ему не нужен ключ сервера — только полное приглашение.

Адрес и ключ сохраняются локально в настройках создателя. Комната закрывается при выходе создателя. После перезапуска VPS создай комнату заново. Сессия ограничена 23 часами, чтобы не использовать истёкшие TURN-доступы; новая комната получает новые ключи.

Для проверки TURN включи «Только через ретранслятор» перед входом на обоих клиентах. Если обычная связь работает, а этот режим нет, проверь TURN, IPv4 и UDP-диапазон. На рабочих клиентах оставляй автоматический режим, если нет причины принудительно использовать сервер.

## Сеть и защита

Служебное соединение идёт через WSS/443; внутри него сохраняется TLS 1.2 ECDHE-PSK/X25519/ChaCha20-Poly1305 между клиентом и создателем. Сервер не получает ключ комнаты и содержимое SDP. Он знает адреса, идентификатор комнаты и метаданные соединений. Публичный HTTPS-сертификат проверяется клиентом.

Медиа и чат используют защищённые WebRTC-соединения, напрямую или через TURN. TURN получает только зашифрованный медиатрафик. Для доступа выдаются временные учётные данные; постоянный TURN-секрет остаётся на VPS. Право создавать комнаты ограничено ключом сервера; приглашение предоставляет доступ конкретной комнате.

TURN здесь работает по UDP/TCP 3478, без TURN-over-TLS. WSS/443 сам по себе не проводит через себя медиа. Сеть, которая блокирует 3478 и прямые соединения, может по-прежнему не пропускать звонок. Для такой сети понадобится отдельная конфигурация TURN/TLS, часто на отдельном IP с портом 443. Этот комплект не обещает обход любых блокировок.

По умолчанию: максимум 32 комнаты, 8 участников в комнате, ограниченные очереди и частота сообщений. Эти ограничения не заменяют защиту провайдера от DDoS. Расход исходящего трафика растёт при ретрансляции видео.

## Обновление и остановка

Сохрани `.env`, `turnserver.conf` и Docker volumes с сертификатами. После замены исходников: `docker compose up -d --build`.
Остановка: `docker compose down`. Активные комнаты при этом закроются.

Протоколы: https://github.com/coturn/coturn/wiki/turnserver и https://webrtc.org/getting-started/turn-server .
